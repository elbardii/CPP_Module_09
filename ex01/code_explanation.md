# شرح الكود سطراً بسطر (Line-by-line Code Explanation) - ex01 (RPN)

هاد الملف كايشرح الكود كامل ديال التمرين بالتفصيل وبالدارجة المغربية، من أول سطر حتى لآخر سطر، باش تكون واجد 100% لأي سؤال فالـ Peer Evaluation.

# الجزء 1: ملف الرأس `RPN.hpp`

---

### 1. الـ Include Guards

```cpp
#ifndef RPN_HPP
#define RPN_HPP
```
- **شنو كيدير:** هادو كايتسماو Include Guards (حراس التضمين).
- **علاش درنا هاد الشي؟**
  باش نمنعو المشكل ديال "Double Inclusion" (إلا تم استدعاء هاد الملف كتر من مرة فـ compilation units مختلفة، الكومبيلر مايعاودش يعرف الكلاس جوج مرات ومايعطيش Error).
- **شنو غادي يوقع إلا حيدناه؟**
  إلا تضمن هاد الملف فجوج بلايص مختالفين، الكومبيلر غايعطي خطأ: `redefinition of 'class RPN'`.

---

### 2. استدعاء المكتبات الضرورية

```cpp
#include <iostream>
#include <string>
#include <stack>
```
- **شنو كيدير:**
  - `<iostream>`: باش نستعملو `std::cout` (لطباعة النتيجة) و `std::cerr` (لطباعة رسالة الخطأ) و `std::endl`.
  - `<string>`: باش نخدمو بـ `std::string` اللي كاتمثل السلسلة النصية ديال العملية الحسابية.
  - `<stack>`: باش نستعملو الـ Container المعتمد فالمشروع وهو `std::stack`.
- **علاش درنا هاد الشي؟**
  حيت الكلاس ديالنا كاتحتاج هاد الأنواع باش تخدم وتعرف الخصائص والدوال ديالها.
- **شنو غادي يوقع إلا حيدناه؟**
  الكومبيلر ماغايعرفش شنو هما `std::string` و `std::stack` وغايحبس بـ `unknown type name`.

### 3. تعريف الكلاس والقسم الخاص (Private)

```cpp
class RPN {
private:
    std::stack<int> _stack;

    bool isOperator(char c) const;
    bool executeOperation(char op);
```
- **شنو كيدير:**
  - كانعرفو الكلاس `RPN`.
  - كانحطو خاصية خاصة (Private attribute): `std::stack<int> _stack`، اللي غاتخزن الأرقام أثناء الحساب.
  - كانعرفو جوج دوال مساعدة خاصة (Private helper methods):
    - `isOperator(char c)`: كاتقولينا واش الحرف هو إحدى العمليات الأربعة (`+`, `-`, `*`, `/`).
    - `executeOperation(char op)`: كاتطبق العملية على آخر جوج أرقام فالـ Stack.
- **علاش درنا هاد الشي؟**
  - **مبدأ الـ Encapsulation (التغليف):** البيانات الداخلية والدوال المساعدة خاصهم يكونو `private` باش حتى شي كود خارجي ما يقدر يعبث بالـ Stack مباشرة.
  - ختارينا `std::stack<int>` حيت الأرقام والعمليات كايخدمو بالأعداد الصحيحة، وخوارزمية RPN كاتعتمد على Stack.
- **شنو غادي يوقع إلا حيدناه؟**
  إلا خلينا الـ Stack عام (Public)، أي واحد يقدر يبدل فيه بطريقة عشوائية ويفسد منطق الحساب.

### 4. القسم العام والـ Orthodox Canonical Form

```cpp
public:
    RPN();
    RPN(const RPN& other);
    RPN& operator=(const RPN& other);
    ~RPN();

    bool calculate(const std::string& expression);
};

#endif
```
- **شنو كيدير:**
  - **Default Constructor:** كايصاوب أوبجيكت جديد بستيك خاوي.
  - **Copy Constructor:** كاينسخ أوبجيكت موجود لأوبجيكت جديد.
  - **Assignment Operator (`operator=`):** كاينسخ محتوى أوبجيكت لآخر باستعمال علامة `=`.
  - **Destructor:** كايحرر الموارد فاش كايسالي عمر الأوبجيكت.
  - **الدالة الرئيسية `calculate`:** كاتاخد السلسلة النصية، كاطبق الحساب، وكاترجع `true` إلا نجحات (وكاتطبع النتيجة) أو `false` إلا كان خطأ.
  - `#endif`: كايسد الـ `#ifndef` ديال أول الملف.
- **علاش درنا هاد الشي؟**
  - السوجي كايفرض صراحة: *"your classes must be designed in the Orthodox Canonical Form"*.
  - تفريق الكود: `main` كايعيط غير لـ `calculate`، وكل التفاصيل محمية لداخل.
- **شنو غادي يوقع إلا حيدناه؟**
  إلا ما احترمناش الـ Orthodox Canonical Form، النقطة ديال المشروع غاتكون ناقصة وماتحترمش معايير موديولات C++ فـ 42.

# الجزء 2: ملف التنفيذ `RPN.cpp`

---

### 1. التضمينات (Includes)

```cpp
#include "RPN.hpp"
#include <sstream>
#include <cctype>
#include <climits>
```
- **شنو كيدير:**
  - `"RPN.hpp"`: كايجيب تعريف الكلاس اللي كتبناه.
  - `<sstream>`: كايوفر `std::stringstream`، اللي كايسمح لينا نقراو الكلمات والرموز من الـ `string` مفروقين بالـ Spaces بكل سهولة.
  - `<cctype>`: كايوفر دالة `std::isdigit` باش نعرفو واش الحرف رقم بين 0 و 9.
  - `<climits>`: كايوفر الثوابت `INT_MAX` و `INT_MIN` باش نتحققو من الـ Overflow.
- **علاش درنا هاد الشي؟**
  هادو أدوات أساسية باش نقراو المعطيات، نتحققو من صحتها، ونحميو الحسابات من الفيضان (Overflow).
- **شنو غادي يوقع إلا حيدناه؟**
  ما غانلقاوش دوال التقطيع والتحقق وغايخرج لينا خطأ فالكومبيلاسيون.

---

### 2. الـ Orthodox Canonical Form (Constructors & Destructor)

```cpp
RPN::RPN() : _stack() {}

RPN::RPN(const RPN& other) : _stack(other._stack) {}

RPN& RPN::operator=(const RPN& other) {
    if (this != &other) {
        this->_stack = other._stack;
    }
    return *this;
}

RPN::~RPN() {}
```
- **شنو كيدير:**
  - `RPN::RPN()`: الـ Constructor الافتراضي، كايستعمل Member Initializer List `: _stack()` باش ينشئ ستيك خاوي.
  - `RPN(const RPN& other)`: الـ Copy Constructor، كاينسخ الـ `_stack` من الأوبجيكت `other`.
  - `operator=`: الـ Assignment Operator، كايتأكد أولاً من الحماية ضد النسخ الذاتي (`if (this != &other)`)، عاد كاينسخ المحتوى، وكايرجع `*this`.
  - `~RPN()`: الـ Destructor، خاوي حيت ما درناش dynamic allocation بـ `new`، والـ `std::stack` كايحرر الذاكرة ديالو راسو أوتوماتيكياً عبر مبدأ الـ RAII.
- **علاش درنا هاد الشي؟**
  باش الكلاس تكون متكاملة وتحترم معيار Orthodox Canonical Form.
- **شنو غادي يوقع إلا حيدناه؟**
  الكلاس ماتكونش مطابقة للمعايير، وإلا مادرتيش فحص `this != &other` تقدر تطيح فمشاكل نسخ الأوبجيكت لنفسه.

### 3. الدالة المساعدة للتحقق من العمليات `isOperator`

```cpp
bool RPN::isOperator(char c) const {
    return (c == '+' || c == '-' || c == '*' || c == '/');
}
```
- **شنو كيدير:** كاتاخد حرف `c`، وكاترجع `true` إلا كان واحد من الربعة: زائد، ناقص، ضرب، أو قسمة، و `false` إلا كان أي حاجة أخرى.
- **علاش درنا هاد الشي؟**
  حيت السوجي حدد حصراً: *"handle operations with these tokens: "+ - / *""*.
- **شنو غادي يوقع إلا حيدناه؟**
  غانضطرو نكتبو هاد الشرط الطويل فبزاف د البلايص، والدالة كاتجعل الكود مقروء ومنظم (Clean Code).

### 4. دالة تطبيق العملية `executeOperation`

```cpp
bool RPN::executeOperation(char op) {
    if (_stack.size() < 2) {
        return false;
    }
```
- **شنو كيدير:** أول سطر كايتحقق واش كاينين على الأقل جوج أرقام فالـ Stack.
- **علاش درنا هاد الشي؟**
  أي عملية ثنائية (Binary operation بحال الجمع أو الضرب) كاتحتاج بالضرورة جوج أعداد (Operands). إلا كان فالستيك غير رقم واحد ولا خاوي، العملية مستحيل تدار وكاتعتابر خطأ.
- **شنو غادي يوقع إلا حيدناه؟**
  إلا حاولتي دير `top()` أو `pop()` والستيك خاوي، البروجرام غايدير سلوك غير محدد (Undefined Behavior) أو Crash (Segmentation Fault).

---

```cpp
    int b = _stack.top();
    _stack.pop();
    int a = _stack.top();
    _stack.pop();
```
- **شنو كيدير:**
  - كاياخد الرقم الفوقاني كـ `b` وكايحيدو بـ `pop()`.
  - كاياخد الرقم اللي تحتو كـ `a` وكايحيدو بـ `pop()`.
- **علاش درنا هاد الشي؟ (سؤال مهم جداً فالتقييم):**
  **"علاش سمينا الأول b والتاني a؟"**
  حيت فـ Reverse Polish Notation، الأرقام كايتحطو بالترتيب من اليسار لليمن:
  مثلاً التعبير: `5 3 -`
  الرقم 5 كيدخل الأول (كيكون لتحت فالستيك).
  الرقم 3 كيدخل من بعدو (كيكون هو الفوقاني فالستيك).
  فاش كانجبدو الفوقاني، هو الرقم الثاني فالعملية (الطرف الأيمن `b = 3`).
  واللي تحتو هو الرقم الأول (الطرف الأيسر `a = 5`).
  والعملية هي: `a - b = 5 - 3 = 2`.
- **شنو غادي يوقع إلا حيدناه ولا قلبناهم؟**
  إلا درتي `b - a`، غاتخرج ليك `3 - 5 = -2`، وهادي نتيجة غالطة تماماً! نفس الشيء فالقسمة: `6 2 /` إلا قلبتيهم غاتعطيك `2 / 6 = 0` بلاصة `3`.

---

```cpp
    long long res = 0;
    if (op == '+') {
        res = static_cast<long long>(a) + b;
    } else if (op == '-') {
        res = static_cast<long long>(a) - b;
    } else if (op == '*') {
        res = static_cast<long long>(a) * b;
    } else if (op == '/') {
        if (b == 0) {
            return false;
        }
        res = static_cast<long long>(a) / b;
    } else {
        return false;
    }
```
- **شنو كيدير:**
  - كايعرف متغير `res` من نوع `long long` باش يحسب فيه النتيجة بلا ما يوقع Overflow مباشر.
  - كايطبق العملية المناسبة حسب الرمز `op`.
  - **فحالة القسمة (`/`):** كايتأكد واش `b == 0`. إلا كان صفر، كايرجع `false` فوراً.
- **علاش درنا هاد الشي؟**
  - **القسمة على صفر:** غير ممكنة رياضياً وكاتسبب `SIGFPE / Crash` فالسيستم، إذن التحقق منها إجباري.
  - **`long long`:** درناها كحماية إضافية باش إلا كانت النتيجة كبر من حجم `int` نقدرو نكشفوها قبل ما يتحول الرقم لحاجة خيالية.
- **شنو غادي يوقع إلا حيدناه؟**
  إلا قسمتي على صفر، البروجرام غايطيح فـ Crash وتاخد 0 فالتقييم.

---

```cpp
    if (res > INT_MAX || res < INT_MIN) {
        return false;
    }

    _stack.push(static_cast<int>(res));
    return true;
}
```
- **شنو كيدير:**
  - كايتأكد بلي النتيجة ما فاتتش حدود الـ `int` (`INT_MAX` و `INT_MIN`).
  - كايحط النتيجة الجديدة الفوق فالـ Stack باستعمال `_stack.push(...)`.
  - كايرجع `true` للإشارة بأن العملية نجحات.
- **علاش درنا هاد الشي؟**
  باش النتيجة المحسوبة ترجع للستيك وتكون واجدة كمعطى للعملية الموالية.
- **شنو غادي يوقع إلا حيدناه؟**
  ماغاتقدرش تكمل العمليات الحسابية المتتالية (بحال `1 2 * 3 +`).

### 5. الدالة الرئيسية لحساب السلسلة `calculate`

```cpp
bool RPN::calculate(const std::string& expression) {
    while (!_stack.empty()) {
        _stack.pop();
    }
```
- **شنو كيدير:** كايفرغ الـ Stack تماماً قبل ما يبدا.
- **علاش درنا هاد الشي؟**
  حماية وتنقية: باش إلا كان هاد الأوبجيكت مستعمل من قبل، مايبقاوش فيه أرقام قديمة تخلط الحساب الجديد.
- **شنو غادي يوقع إلا حيدناه؟**
  إلا تندهات الدالة جوج مرات، الحساب الثاني غايتخلط مع بقايا الحساب الأول.

---

```cpp
    std::stringstream ss(expression);
    std::string token;

    while (ss >> token) {
```
- **شنو كيدير:**
  - كايحط السلسلة النصية `expression` فـ `std::stringstream`.
  - كايقرا الكلمات والرموز وحدة بوحدة (`token`) مفروقين بالفراغات (Spaces أو Tabs).
- **علاش درنا هاد الشي؟**
  - `stringstream` كاتدير تصفية الفراغات (Whitespace skipping) أوتوماتيكياً وكاتعطيك كل عنصر بوحدو.
  - طريقة نقية وساهلة وبدون تعقيد `strtok` ولا مؤشرات الـ C.
- **شنو غادي يوقع إلا حيدناه؟**
  غانضطرو نكتبو لوب بيدينا باش نقطعو السطور ونتعاملو مع المسافات المتعددة، وهادشي كيعقد الكود بلا فائدة.

```cpp
        if (token.length() == 1 && std::isdigit(token[0])) {
            _stack.push(token[0] - '0');
        } else if (token.length() == 1 && isOperator(token[0])) {

                return false;

        } else {
```

- **شنو كيدير:**
  - **الحالة 1 (رقم):** إلا كان الطول ديال الـ token هو 1 بالضبط وكان رقم (`isdigit`):
    - كايحولو لـ `int` بطرح كود الآسكي `'0'` (`token[0] - '0'`).
    - كايحطو فالـ Stack بـ `_stack.push(...)`.
  - **الحالة 2 (عملية):** إلا كان الطول هو 1 وكان علامة من العمليات الأربعة:
    - كايعيط لـ `executeOperation` باش تنفذ العملية.
    - إلا فشلات الدالة (مثلاً قسمة على صفر أو ماكافيينش الأرقام)، كايرجع `false` فوراً.
  - **الحالة 3 (أي شيء آخر):**
    - كلمة فيها كتر من حرف (بحال `"12"`، ولا `"(1"`، ولا `"-5"`).
    - حرف ماشي رقم وماشي عملية (بحال `'a'`, `'$'`).
    - كايرجع `false` مباشرة حيت هادا خطأ إدخال!
- **علاش درنا هاد الشي؟**
  - السوجي فرض بوضوح أن الأرقام المدخلة كاتكون **صغر من 10** (يعني أرقام مفردة من `0` حتى `9`):
    *"The numbers used in this operation and passed as arguments will always be less than 10."*
  - إذن أي توكن الطول ديالو ماشي 1 كايتعتابر خطأ.
- **شنو غادي يوقع إلا حيدناه؟**
  البرنامج غايقبل مدخلات غير صحيحة بحال `"(1 + 1)"` أو أرقام كبيرة وما غايحترمش معايير السوجي.

---

```cpp
    if (_stack.size() != 1) {
        return false;
    }

    std::cout << _stack.top() << std::endl;
    return true;
}
```
- **شنو كيدير:**
  - كايتأكد واش بعد ما سالات قراءة السلسلة كاملة، بقى **عنصر واحد فقط** فالـ Stack.
  - إلا كان الحجم ماشي 1 (مثلاً بقاو 2 أرقام بحال `"1 2"`، ولا الستيك خاوي بحال `""`): كايرجع `false`.
  - إلا كان الحجم هو 1 بالضبط: كايطبع هاد الرقم النهائي فالـ `std::cout` وكايرجع `true`.
- **علاش درنا هاد الشي؟**
  - التعبير الرياضي الصحيح فـ RPN، بعد نهاية كل العمليات، خاص يخلي رقم واحد فقط هو النتيجة النهائية.
  - إلا بقاو أرقام شايطة، يعني العملية ناقصينها علامات وما كاملاتش (Syntax error).
- **شنو غادي يوقع إلا حيدناه؟**
  تعبير بحال `"1 2"` أو `"3 4 5 +"` غايعطيك نتيجة ناقصة ومغالطة، وماغاديش تكتشف الأخطاء.

# الجزء 3: ملف البداية `main.cpp`

---

```cpp
#include "RPN.hpp"
#include <iostream>

int main(int argc, char* argv[]) {
    if (argc != 2) {
        std::cerr << "Error" << std::endl;
        return 1;
    }

    RPN rpn;
    if (!rpn.calculate(argv[1])) {
        std::cerr << "Error" << std::endl;
        return 1;
    }

    return 0;
}
```
- **شنو كيدير:**
  1. كايتأكد بلي عدد الـ Arguments هو 2 بالضبط (`argc == 2`)، يعني اسم البرنامج والمعادلة فقط (`./RPN "expression"`).
  2. إلا كان عدد الـ Arguments ماشي 2 (مثلاً ما عطاش والو، ولا عطا كتر من argument)، كايطبع `Error` فالـ `std::cerr` وكايسالي بـ `return 1`.
  3. كاينشئ أوبجيكت `RPN rpn;`.
  4. كايعيط للدالة `rpn.calculate(argv[1])`.
  5. إلا رجعات `false` (يعني كان خطأ فالصيغة أو فالحساب)، كايطبع `Error` فالـ `std::cerr` وكايسالي بـ `return 1`.
  6. إلا رجعات `true`، الدالة راها طبعات النتيجة فالـ `std::cout`، والبرنامج كايسالي بنجاح بـ `return 0`.
- **علاش درنا هاد الشي؟**
  - **بساطة `main.cpp`:** الموضوع والتعليمات كايطلبو صراحة أن `main.cpp` يبقى خفيف وبسيط بزاف وفيه غير الفحص واستدعاء الكلاس.
  - **معايير الأخطاء:** السوجي كايطلب طباعة رسالة الخطأ على `std::cerr`.
- **شنو غادي يوقع إلا حيدناه؟**
  إلا دخل المستعمل بلا Arguments ولا دخل شي حاجة غالطة ومادرناش التحقق، البرنامج غايطيح فـ Segmentation Fault أو يخرج بنتائج غير متوقعة.
