# شرح تمرين Bitcoin Exchange (ex00) بالدارجة المغربية

---

## 1. شنو كايطلب منا التمرين؟ (What the exercise asks us to do)

التمرين باختصار كايطلب منا نصاوبو بروجرام سميتو `btc`.
هاد البروجرام الدور ديالو هو يحسب شحال كانت كاتسوا واحد الكمية ديال الـ Bitcoin فواحد التاريخ محدد فالماضي.

باش يدير هاد الحساب، البروجرام كايعتمد على جوج حوايج:
1. **قاعدة بيانات (Database):** ملف سميتو `data.csv` كايجي مع التمرين، فيه التاريخ وسعر حبة بيتكوين وحدة داك النهار (`date,exchange_rate`).
2. **ملف الإدخال (Input file):** ملف كايعطيه المستعمل فالـ arguments (مثلاً `./btc input.txt`)، فيه شحال من بيتكوين بغينا نحسبو القيمة ديالها وفأي تاريخ (`date | value`).

البروجرام كايقرا كل سطر من ملف الإدخال، كايتأكد واش التاريخ صحيح والقيمة صحيحة، من بعد كايقلب على داك التاريخ فقاعدة البيانات:
* إلا لقى نفس التاريخ بالضبط، كايضرب القيمة فالـ exchange rate.
* إلا مالقاش داك التاريخ، كاياخد **أقرب تاريخ قديم عليه** (lower date / closest past date) وكايضرب فيه.
* إلا كان التاريخ غالط، ولا القيمة سالبة، ولا القيمة كبر من 1000، كايطبع رسالة خطأ مناسبة وبلا ما يوقف البروجرام، كايكمّل يقرا باقي السطور.

---

## 2. شنو هو الإدخال؟ (Input)

البروجرام كاياخد مسار ملف نصي فالـ arguments:
```bash
./btc input.txt
```

الملف كايكون مكتوب بهاد الفورما:
```text
date | value
2011-01-03 | 3
2011-01-03 | 2
2011-01-03 | 1.2
2012-01-11 | -1
2001-42-42
2012-01-11 | 2147483648
```

الشروط ديال الإدخال:
- السطر الأول عادة هو الهيدر `date | value`.
- كل سطر فيه التاريخ و القيمة مفروقين بـ `" | "` (سبايس، بايب، سبايس).
- التاريخ خاصو يكون: `YYYY-MM-DD` (العام - الشهر - النهار).
- القيمة خاصها تكون إما عدد صحيح موجب (positive integer) ولا عدد بالفاصلة (float/double) محصور بين `0` و `1000`.

---

## 3. شنو خاص يخرج فالـ Output؟

النتيجة كاتطبع فالـ standard output بهاد الفورما:
```text
date => value = result
```
حيث أن `result = value * exchange_rate`.

أمثلة على المخرجات:
```text
2011-01-03 => 3 = 0.9
2011-01-03 => 1.2 = 0.36
Error: not a positive number.
Error: bad input => 2001-42-42
Error: too large a number.
```

## 4. القواعد المهمة ديال السيستيم (Subject Rules)

1. **المعيار C++98:** ماكاينش `auto`، ماكاينش `nullptr`، ماكاينش `std::to_string`، ماكاينش Range-based for loops.
2. **الرايات (Flags):** الكود خاصو يتيليشارجا ويتكومبيلا بـ `c++ -Wall -Wextra -Werror -std=c++98`.
3. **Orthodox Canonical Form:** الكلاس `BitcoinExchange` خاصها تحتوي على:
   - Default constructor
   - Copy constructor
   - Copy assignment operator (`operator=`)
   - Destructor
4. **قاعدة الحاويات الصارمة (Container Restriction):**
   - الـ Container اللي غانستعملوه هنا (وهو `std::map`) **ممنوع نهائياً** نعاودو نستعملوه فـ `ex01` ولا فـ `ex02`.
5. **معالجة الأخطاء:**
   - إلا ما تفتحش الملف: `Error: could not open file.`
   - إلا كانت القيمة سالبة: `Error: not a positive number.`
   - إلا كانت القيمة كبر من 1000: `Error: too large a number.`
   - إلا كان السطر مافيهش التاريخ مقاد ولا الفورما معيبة: `Error: bad input => [السطر]`.

## 5. المفاهيم اللي خاصك تفهمها مزيان (Core Concepts)

### 1. مفهوم STL (Standard Template Library)
الـ STL هي مكتبة واجدة فـ C++ كاتوفر لينا هياكل بيانات (Containers) و خوارزميات (Algorithms). بلا ما نحتاجو نبنيو Linked List ولا Binary Tree من الزيرو بحال كيف كنا كانديرو فـ C.

### 2. مفهوم Key-Value Pair
فـ `std::map`، البيانات كايتخزنو على شكل أزواج:
- **Key (المفتاح):** هو التاريخ (`std::string` بحال `"2011-01-03"`).
- **Value (القيمة):** هو سعر الصرف (`double` بحال `0.3`).

### 3. الترتيب الأبجدي كايعطينا الترتيب الزمني!
علاش التواريخ مكتوبة بـ `YYYY-MM-DD`؟
حيت إلا قارنت جوج سترينغات بهاد الفورما:
`"2011-01-03" < "2011-01-09"` -> هاد المقارنة صحيحة!
إذن فاش كاندخلو التواريخ لـ `std::map`، هو راسو كايتكلف يرتبهم تصاعدياً من القديم للجديد.

## 6. إينا STL Container استعملنا وعلاش؟ (Container Choice & Justification)

> **سؤال كايتسول ديما فالـ Peer Evaluation:**
> **"علاش ختاريتي `std::map` وما ختاريتيش مثلاً `std::vector` ولا `std::list`؟"**

الجواب الواضح والبسيط:
1. **البحث السريع المباشر بالمفتاح (Key Lookup):**
   حنا عندنا علاقة بين تاريخ وسعر (`Date -> Rate`). الـ `std::map` مبني على شجرة بحث ثنائية متوازنة (Red-Black Tree)، كايعطينا بحث فـ $O(\log N)$.
2. **البيانات مرتبة تلقائياً (Automatic Sorting):**
   `std::map` كايحافظ على التواريخ مرتبة زمنياً بدون أي مجهود منا.
3. **أهم ميزة: خوارزمية `upper_bound` و `lower_bound`:**
   المطلوب فالتمرين: إلا مالقيتيش التاريخ، خد أقرب تاريخ أصغر منو (lower date).
   فـ `std::map`، الفانكشن `upper_bound(date)` كاتلقى أول عنصر كبر قطعا من التاريخ المطلوب، و إلا رجعنا بخطوة وحدة اللور (`--it`)، كانلقاو مباشرة التاريخ الأصغر منو أو اللي كايساويه! هاد العملية سهلة وسريعة بزاف فـ `std::map` ومستحيل ديرها بهاد البساطة فـ `vector` بلا ما تعاود ترتب وتقلب بيدك.
4. **احترام قواعد الموديول:**
   `ex01` غايحتاج `std::stack`، و `ex02` غايحتاج `std::vector` و `std::deque`. إذن `std::map` كايجي مفصّل ومثالي لـ `ex00`.

## 8. الحالات الخاصة (Edge Cases) اللي تعاملنا معاها

1. **السنوات الكبيسة (Leap Years):**
   شهر فبراير (02) كايحتوي على 29 يوم إلا كانت السنة كبيسة، و 28 يوم إلا كانت عادية.
   القاعدة الحسابية:
   السنة كبيسة إلا كانت كتقسم على 4 وما كتقسمش على 100، أو كتقسم على 400.
   - `2012-02-29` -> سنة كبيسة (صالحة).
   - `2011-02-29` -> سنة عادية (غير صالحة، كايعطي `bad input`).
2. **أيام الشهور المختلفة:**
   أشهر (4، 6، 9، 11) فيها 30 يوم، أشهر (1، 3، 5، 7، 8، 10، 12) فيها 31 يوم. إذن `2011-04-31` تاريخ خاطئ.
3. **تاريخ قبل بداية قاعدة البيانات:**
   أول تاريخ فـ `data.csv` هو `2009-01-02`. إلا دخل شي حد `2001-01-01`، ماكاينش تاريخ فـ DB أصغر منو، البروجرام كايطبع `Error: bad input`.
4. **تاريخ غير موجود ولكن بعد البداية:**
   مثلاً `2011-01-04` ماكايناش فـ DB. البروجرام كاياخد تلقائياً أقرب تاريخ قبل منها (وهو `2011-01-03`) وكايحسب بيه.
5. **الحدود 0 و 1000:**
   القيمة `0` مقبولة، والقيمة `1000` مقبولة. لكن `1000.1` كاتعطي `too large a number`، و `-0.01` كاتعطي `not a positive number`.
6. **ملف فارغ (Empty file):**
   البروجرام كايقراه عادي، ما كايطبع والو وما كايوقعش ليه Crash.

## 9. أخطاء شائعة كايديروها الناس (Common Mistakes)

1. **استعمال `find()` بوحدها:**
   إلا استعملتي غير `find(date)`، إلا كان التاريخ ماكاينش فالـ DB غايعطيك خطأ، بينما المطلوب هو تاخد التاريخ اللي قبل منو!
2. **نسيان السنوات الكبيسة (Leap Year check):**
   بزاف ديال الناس كيديرو فبراير ديما 28 ولا ديما 29، وفالـ Evaluation كايتيستيو بـ `2012-02-29` وكايسقطو.
3. **توقيف البروجرام فاش يلقى خطأ (exit upon error):**
   المطلوب صراحة فالتمرين: البروجرام يطبع الخطأ ويكمل قراءة باقي السطور وما يوقفش حتى يسالي الملف كامل.
4. **Leaks ديال الذاكرة:**
   استعمال `new` بلا `delete`. حنا ما استعملناش `new` نهائياً، اعتمدنا على `std::map` و الـ Stack Memory، إذن الذاكرة نقية 100%.

## 12. شنو خاصك تشرح للمصحح (Peer Evaluation Defense)

1. **شنو هو الدور ديال الكلاس؟**
   كلاس `BitcoinExchange` مسؤولة على قراءة `data.csv`، وتخزين الأسعار فـ `std::map`، ومعالجة ملف الإدخال سطر بسطر.
2. **علاش درنا Orthodox Canonical Form؟**
   حيت هادشي مطلوب فقواعد C++ Module، الكلاس فيها Default constructor، Copy constructor، Assignment operator، و Destructor.
3. **كيفاش كاتجيب أقرب تاريخ أصغر؟**
   كانستعملو `_database.upper_bound(date)`. هاد الفانكشن كاتعطينا أول تاريخ كبر قطعا من التاريخ المطلوب، وكنرجعو بحبة وحدة اللور بـ `--it` فكنطيحو مباشرة فأقرب تاريخ أصغر من أو يساوي التاريخ المطلوب.
4. **واش كاينين Leaks؟**
   ما كاين حتى شي `new` ولا `malloc` فالمشروع، والـ `std::map` كايحرر الذاكرة ديالو راسو فاش كايتسالي الـ Scope.
